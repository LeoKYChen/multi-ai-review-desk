# Multi-AI v1.0｜純雲端背景審查（授權前原型）

## 需求與方向
使用者希望手機或 Mac 打開私有網址，交辦一次 Word／文字，ChatGPT 與 Gemini 在**瀏覽器關閉後仍可完成**六份分析，最後由使用者人工決定。故不能依賴本機 CLI，也不能只靠前端連續呼叫 /advance。

## 實作：背景佇列（開發分支，未部署）

- Cloudflare Worker 收到本人授權的開始審查要求，**不直接呼叫模型**，而是在 D1 原子標記 `queue_requested=1`，送出僅含任務 UUID 的 Queue 訊息。
- Queue consumer 依序處理：兩模型獨立分析 → 兩模型交叉審查 → 兩模型各自最終修正建議。每一階段必須先寫入 D1，才會發下一階段訊息。
- 相同任務重複按開始鍵不會重複排程；目前執行中的任務受到原有 D1 lock 保護。
- 模型呼叫失敗會**停止自動重試付費呼叫**，保留既有成果，待本人核對後重新送出；不產生虛構回覆。
- 由本人決定最終結果，保留歷次回合與退回理由。資料只儲存在 D1，不接 R2 或 Google Drive。
- 本原型的 `BACKGROUND_JOBS_ENABLED` 與 `MODEL_API_ENABLED` **預設皆關閉**。建立 Queue、部署 Worker、設定私人 Access、設定 OpenAI/Gemini 伺服器憑證都需要外部授權；目前未進行。

## 關鍵注意事項
1. 這是**非正式環境**的功能程式，不是已通過真實雙模型授權或遠端 D1 E2E。
2. Cloudflare Queues 並非免費無限量；請在部署前確認 [官方費用](https://developers.cloudflare.com/queues/platform/pricing/) 與月度／每日限制。
3. 為避免公開資料，Cloudflare Access／私人域名與 Worker 伺服器安全驗證必須先完成；不可先公開部署再補防護。
4. 若正式 Queue 執行時發生 Worker crash 或重送，仍需針對「模型已計費但結果尚未持久化」設計可觀測性與重試決策；現有 D1 呼叫次數上限不能保證完全避免超額費用。
5. Cloudflare Queue 的 consumer/producer binding、真實 Access、帳號與模型授權需在將來另外驗收，不能以模擬測試代替。
6. **使用者要求遇到 API Key、Token 等即停止，故目前僅進行無憑證程式與測試，保留所有部署開關為關閉。**
