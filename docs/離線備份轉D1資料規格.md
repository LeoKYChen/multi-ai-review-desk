# 離線 v0.8 備份轉為 D1 匯入計畫（v0.9）

> **目前僅能在自己電腦離線執行轉換與模擬驗證。此功能不會連線 Cloudflare，也不會修改遠端 D1。**

## 用途

你目前可用的 [v0.8 離線工作臺](../offline/index.html) 會匯出 `version: 8`、`format: multi-ai-offline-v0.8` 的 JSON。這不是 D1 資料庫本身的備份。要在未來將這些任務帶到雲端，需要逐筆驗證並轉換為四種關聯資料：

| 離線內容 | 未來 D1 資料表 |
|---|---|
| 任務名稱、交辦指令、Word 純文字、分類 | `tasks` |
| 每次重新討論／六階段的回合 | `task_rounds` |
| ChatGPT/Gemini 每階段手動貼回的回覆 | `ai_outputs` |
| 人工採納、退回原因與時間 | `human_decisions` |

**重要設計**：
- 不丟棄原始交辦、文件文字、回合及審查紀錄，不覆寫已存在的 D1 任務。
- 所有網頁版 AI 回覆必須保留 `source=manual_unverified`，不會變成「已透過官方 API 驗證」。
- 原先離線 ID 若非標準 UUID，產生固定且可重現的 UUIDv8；同一原始備份重跑會映射到相同 ID。若日後匯入到已有同 ID 的 D1，必須報錯，不可安靜跳過或覆寫。
- 人工退回要有理由；每回合必須符合 AI 獨立初稿→交叉審查→個別建議的順序，才能開始新回合。
- 輸入上限：8 MB JSON、100 筆任務、每筆最多 30 回合，每回合最多六份 AI 回覆。
- 實際資料庫遷移要求執行 **0001～0005**；本工具不做遷移，也不修改任何資料庫。

## 如何操作（需要 Node.js 22 或更新版本）

在已下載的 repository 資料夾開啟終端機。

**步驟一：只檢查，不寫出檔案。**

```bash
node tools/convert-offline-backup.mjs "你的離線備份.json"
```

執行後只顯示版本是否正確、任務／回合／意見／人工核定的筆數，以及原備份的 SHA-256。不會輸出私人交辦文字。

**步驟二：另外產生匯入計畫（選用）。**

```bash
node tools/convert-offline-backup.mjs "你的離線備份.json" --output "private-imports/我的匯入計畫.json"
```

請先確認備份已安全保存。工具拒絕覆寫原始檔或已存在的輸出計畫。`private-imports/` 預設加入 `.gitignore`。

**注意：匯入計畫是未加密的 JSON，裡面有所有原始文字與討論紀錄。不得提交 GitHub、公開分享或轉存到不安全的位置。**

## 自動測試及驗收

- Node 測試：回合順序、UUID 穩定映射、退回理由、未知模型來源、惡意 SQL 文字、不合法／過長資料。
- Python + SQLite 整合測試：套用 0001～0005 migrations 到全新的記憶體資料庫，透過參數化 SQL 在交易中匯入計畫，核對任務、回合、模型意見、人工決定、來源與原文。
- 同份資料重新匯入時必須因 PK 重複而失敗，且回滾，不新增第二份，也不覆寫既有任務。

**尚未完成**：真正的 Cloudflare D1 原子匯入、衝突清單預覽、D1 遠端備份還原驗收、匯入後網頁檢查。正式匯入應採 Cloudflare D1 `batch()` 原子交易並確認實際限制，**不能直接把本專案的 SQLite 本地測試 SQL 匯入正式站**。

官方說明：https://developers.cloudflare.com/d1/worker-api/d1-database/#batch
