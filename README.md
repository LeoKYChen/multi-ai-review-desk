# Multi-AI 協作工作臺

獨立的雙 AI 文件審查工作臺，與觀護人學習平臺分開維護。使用 Sites 版已驗證的靜態介面，不需要 D1、Cloudflare Token 或伺服器。

## 使用方式

1. 開啟 `docs/index.html`，或使用部署後的網站。每次開啟預設為「手動審查」，不需要 API 金鑰。
2. 建立任務，或從觀護人學習平臺匯入題目及答案，再按「開始本回合」。
3. 依序複製提示詞、開啟對應 AI 網頁，將完整回覆貼回並儲存。
4. 兩個 AI 各自分析、交叉評論、各自修訂，共六份意見，最後由你核定，才可回傳原題。
5. 需要自動執行時，於操作模式選「進階：API 自動審查」，再展開 API 設定，從 OpenAI、Gemini、Claude 任選兩家，填入金鑰與文字模型並測試連線。API 執行仍需確認，可能另行計費。

模式只控制介面顯示，不寫入任務備份，也不會清除題目、答案、既有評語或人工核定。重新整理會回到手動模式；已有 API 回合的服務／模型綁定仍保留，須重新選擇進階模式並填入相同設定才可繼續 API 執行。網頁聊天訂閱與 API 用量分開。

目前 `main` 網站介面不顯示 Cloudflare 雲端版入口、區塊或提示。雲端原型分支、底層程式、診斷／部署工作流程及既有資料保留，本次不合併雲端草稿 PR #1。

互評須指出具體主張、不足、影響、理由、查證狀態及修正方式。修訂須回應哪些批評採納、不採納或保留待查證；不強求一致。

## 金鑰與資料

- 金鑰由使用者自行填寫，只留在本次頁面記憶體，不放入原始碼、GitHub Secrets、localStorage 或 JSON 備份。
- API 請求由瀏覽器直接送到選定的服務商；服務商可能按使用量收費。
- 文件及相關討論會隨請求送到服務商。任務紀錄另存於目前瀏覽器，不會自動上傳 GitHub 或跨裝置同步。
- 換網址或裝置前先匯出 JSON，再於新站還原。不要將個人備份、金鑰或未公開文件提交到儲存庫。
- 法律引用仍需人工查證；這一版不具備即時法源檢索工具。

## GitHub Pages

網站內容只發佈 `docs/`，不包含既有 Cloudflare 診斷或測試分支程式。

1. 先確認儲存庫方案與網站公開範圍。私人儲存庫不代表 Pages 網站只對自己開放；未確認前勿啟用。
2. 在 Settings → Pages 將 Source 設為 GitHub Actions。
3. 網站變更合併至 `main` 後自動發佈；也可從 Actions 手動執行「Deploy standalone AI review desk to GitHub Pages」。

部署只接受 `main`；網站變更合併後由現有工作流程自動發佈，也可手動執行。這不會觸發既有的 Cloudflare 手動部署。選擇進階 API 模式時，須自行確認服務的連線與金鑰限制。
